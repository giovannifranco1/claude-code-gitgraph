# ARCHITECTURE
- **Módulos puros** (sem `$`): `hooks/log.ts` (parse do `git log`), `hooks/lanes.ts` (layout do grafo), `hooks/detect.ts` (pré-validação de nome de branch), `hooks/format.ts` (datas, truncamento). Testados por `*.test.ts`.
- **Wiring** em `hooks/register.tsx`: registra `/gitgraph`, roda git, guarda resultado em `$.state`, desenha o `Pane` num hook `ui.render`, após cada `tool.call` do Bash e a cada 5s compara a assinatura do repo (status v2 + for-each-ref) e recarrega só se mudou, trata `ui.press`/`ui.input` via handlers dos elementos.
- **Regra da engine:** `$` nunca vai dentro de objetos; funções de render recebem `$` como 1º parâmetro e um `Ctx` sem `$`.
- **Render virtualizado:** só as linhas na janela viram elementos. Fora do terminal docked a engine rola a árvore: linhas na janela (+15), o resto são espaçadores; toda linha tem altura explícita (`line()`, `framed()`), o que torna os espaçadores exatos.
- **Scroll próprio no terminal docked:** o hook `ui.scroll` segura a janela da engine (sem `next`) e move `scrollTop` (`$.state`); a árvore tem a altura do pane (`bodyRows`) e só a janela de linhas (`rows-window`, `windowAt`) muda sob cabeçalho e rodapé fixos. A geometria desenhada (`ownScroll`) é escrita pelo render e lida pelo hook e pela busca.
- **Modais:** no terminal docked, o git flow (menu, set-up, start, finish, confirmação), o menu de uma ref e as ações de um commit flutuam sobre o grafo (`renderDialog`, uma `Box` absoluta sobre uma camada de espaços), uma de cada vez (`pinnedDialog`). Fora dele, o mesmo conteúdo fica no rodapé / sob a linha.
- **Pílulas por segmentos:** `pillProps` monta os segmentos (nome, remote no tom escuro da cor, ícone de check / tag / fantasma); `badgeWidth` mede o mesmo com 3 células por ícone. A largura do grafo segue as linhas da janela (`widestIn`), num layout em duas passadas.
- **Cache de grafo por versão:** o render lê `graphVersion` (pequeno) e usa `graphCache` (grafo, `maxCells`, índice hash→linha) em vez de trazer o grafo inteiro do `$.state` a cada passo.
- **Client modules:** `pill.tsx` (pointer: direito abre menu, esquerdo seleciona na hora, duplo faz checkout e devolve a seleção de antes do primeiro clique) e `spinner.tsx` rodam no lado do terminal; só terminal/desktop desenham `Client` (vscode tem stub).
- **UI transitória** fechada num lugar só (`CLOSED`); ações git passam por `runActions` (trava, spinner, toast por falha, recarga).
- **Fluxo:** comando/refresh → `git log` → parse → lanes → `$.state` (graph) → render lê `$.state` e redesenha automaticamente.
